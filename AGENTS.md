# polybot

Autonomous quantitative trading bot for Polymarket temperature (and TSA) prediction markets: multi-model weather forecasts → probability distribution over buckets → Kelly-sized bets when model price diverges from CLOB market price. Full architecture and strategy details: [README.md](README.md).

## Commands

```bash
source venv/bin/activate          # Python 3.12; deps installed directly in the venv

python main.py --scan             # fetch markets, run signal pipeline, paper-trade edges
python main.py --scan-tsa         # TSA (passenger) market pipeline
python main.py --backfill         # pull history, bias corrections, climatology
python main.py --nowcast          # live mid-day temps, update position confidence
python main.py --resolve          # settle open trades with final temperatures
python main.py --stats            # full metrics dashboard (CLI)
python main.py --dry-run          # combine with --scan/--resolve: no writes

python daemon.py                  # scheduler: model-run scans, nowcasts, exit-scans, resolves
python web_dashboard.py           # Flask dashboard (live P&L + open positions)
python scripts/gen_clob_creds.py  # generate CLOB API credentials
```

There are no tests and no `requirements.txt`. Key deps (already in `venv/`): `py-clob-client`, `flask`, `requests`, `python-dotenv`, `scipy`, `numpy`. If you add a dependency, install into the venv and note it here.

## Architecture

Flat module layout at the repo root, with four domain packages:

- `data/` — external data ingestion: `openmeteo.py` (5 NWP models: GFS, ECMWF, ICON, GEM, MF, HRRR), `noaa.py`/`wunderground.py` (station observations), `polymarket.py` (Gamma/CLOB prices), `climatology.py`
- `signals/` — alpha pipeline: `ensemble.py` → `nowcaster.py` → `edge_calculator.py` (core engine: Student-t bucket probability → edge → Kelly size), with per-city `bias_corrector.py`, `neighbor_check.py`, `confidence_tier.py`, `consistency_checker.py` gates
- `broker/` — execution: `paper_broker.py` (simulated fills at CLOB prices), `live_broker.py` (real orders via py-clob-client), `position_manager.py` (resolution + P&L)
- `metrics/` — `calibration.py` (shrinkage factor), `sharpe.py`, `pnl.py`, `reporting.py`

Dependency direction: `data/` → (nothing); `signals/` → `data/` + `config`; `broker/` → `signals/` + `db`; top-level scripts orchestrate all of it. `config.py` holds every tunable parameter with inline empirical justifications — read it before touching trading logic.

## Configuration & environment

- `.env` (never commit; see `.env.example`): `POLYMARKET_PRIVATE_KEY`, `POLYMARKET_PROXY_ADDRESS`, `POLYMARKET_SIGNATURE_TYPE`, `POLYMARKET_API_KEY/SECRET/PASSPHRASE` (generated by `scripts/gen_clob_creds.py`).
- All risk/threshold parameters live in `config.py` (`MIN_EDGE`, `KELLY_FRACTION`, `MAX_TRADE_USDC`, NO-entry gates, ensemble std gates, etc.). Values there were tuned from resolved-trade history — comments explain each; do not loosen them without evidence.

## Pitfalls

- **Paper vs live DB**: `db.py` switches `DB_PATH` between `paper_trades.db` and `live_trades.db` depending on live mode. Never point writes at the wrong DB; treat the live one as production money.
- **Lockfile**: `--scan`/`--backfill` hold `polymarket_bot.lock` (fcntl, stale-PID-aware). Don't run two scans concurrently; don't delete the lock manually.
- **SQLite WAL**: `paper_trades.db-shm`/`-wal` files exist while a process is open. Don't commit them; don't move/copy the DB while the daemon runs.
- **Config drift between environments**: `polybot.service`/`polybot-dashboard.service` deploy to `/home/aadichauhan/polymarket_bot` on a Linux host — paths and state there differ from this macOS checkout.
- **External APIs**: Open-Meteo, NOAA/ASOS, Polymarket Gamma/CLOB have rate limits; scans hit several models per city. Use `--dry-run` when experimenting.
- **`.wayfinder/`**: local wayfinder map + tickets from past planning sessions — historical, not active tickets (issues now go to GitHub per the tracker config below).
